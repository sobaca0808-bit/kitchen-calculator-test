# Публикация тестового калькулятора: Issue №2

Все действия ниже относятся **только** к `sobaca0808-bit/kitchen-calculator-test`.
Рабочий репозиторий `sobaca0808-bit/kitchen-calculator`, его настройки Pages и PR №2 не трогаем.

## Что уже есть

В корне тестового репозитория находятся `index.html`, `styles.css`, `js/calculations.js`, `js/seed.js`, `js/storage.js`, `js/recipe-view.js` и `js/app.js`. Это тестовая preview-копия рабочего PR №2. Она уже содержит:

- открытие сохранённого блюда в виде технологической карты и отдельную кнопку редактирования;
- временный пересчёт числа порций без перезаписи рецепта;
- печать A4 с ценами и без финансовых данных.

Относительные пути подходят для папки проекта на GitHub Pages. `.nojekyll` указывает Pages отдавать готовые статические файлы без обработки Jekyll. Сборка, платные сервисы и новый workflow не нужны. Старую вложенную папку `kitchen-calculator-preview-pr2-browser` не выбирайте источником сайта.

## Состояние проверки

Настройки Pages через API из этой среды прочитать не удалось: обращение к `api.github.com` отклонено сетевым прокси. Попытка открыть публичную страницу в Chromium также завершилась `ERR_TUNNEL_CONNECTION_FAILED`. Поэтому текущие Source/Branch/Folder не считаются подтверждёнными, настройки автоматически не менялись, новая публикация не заявляется успешной.

Браузерные сценарии запускаются на локальном сервере по пути `/kitchen-calculator-test/`, а не только из корня `/`. Это проверяет загрузку CSS, скриптов и действия калькулятора в той же структуре адреса, что и у Pages. Все браузерные контексты временные; данные вымышленные.

## Что нажать владельцу

1. Сначала проверьте и примите **PR №1 тестового репозитория**, если он ещё открыт. PR по Issue №2 основан на его ветке, чтобы сохранить проверки изоляции. После принятия PR №1 у PR по Issue №2 выберите **Edit → base: main**, если GitHub сам не сменил базу. Посмотрите изменения и примите этот PR только в тестовом репозитории. Codex автоматически ничего не объединяет.
2. Откройте **[Settings → Pages тестового репозитория](https://github.com/sobaca0808-bit/kitchen-calculator-test/settings/pages)**. Если там уже указаны **Deploy from a branch → main → / (root)** и показан адрес тестового сайта, оставьте настройки как есть.
3. Если тестовый Pages ещё не настроен, выберите **Source: Deploy from a branch**, **Branch: main**, **Folder: / (root)** и нажмите **Save**. Дождитесь успешного `pages build and deployment` в **Actions**. Не добавляйте Custom domain рабочего калькулятора. Если уже используется другой способ публикации, сначала проверьте его, не переключайте настройки вслепую.
4. Откройте **Visit site** на странице Pages. Используйте адрес, который показал сам GitHub, на ПК и телефоне. На странице должна быть отметка **«ТЕСТ PR №2»**. Открытие исходного файла на `github.com` не проверяет сайт.

Сообщённый владельцем ожидаемый адрес — `https://sobaca0808-bit.github.io/kitchen-calculator-test/`. Это ориентир для сравнения с **Visit site**, а не заявление о подтверждённой в этой среде доступности.

## Безопасная проверка на ПК и телефоне

1. Откройте тестовый сайт в Chrome. Создайте вымышленный продукт, полуфабрикат и блюдо; сохраните. Несколько нажатий «Сохранить» должны оставить одну запись.
2. Откройте блюдо: сначала показывается карта. Нажмите «Изменить», поменяйте заметку и сохраните. Перезагрузите страницу и снова откройте блюдо.
3. Запомните исходное число порций, выберите 10. Количества и стоимость должны измениться. После повторного открытия исходный рецепт должен остаться прежним.
4. Выберите **ПОКАЗЫВАТЬ ЦЕНЫ: ДА**, затем **Печать**. В диалоге выберите A4 и «Сохранить как PDF». Повторите с **НЕТ**: цен и себестоимости в карте и PDF быть не должно. На телефоне доступность системного диалога печати зависит от браузера и установленных служб печати.
5. Экспортируйте тестовый JSON и импортируйте его обратно. При отмене подтверждения импорта данные не должны заменяться. Попробуйте уйти из несохранённой формы и отменить переход.

Рабочие резервные копии для этих действий не нужны. Тестовое приложение использует `kitchen-calculator-pr2-browser-test-v1`, не читает и не записывает `kitchen-calculator-v1`. Проекты Pages одного владельца имеют общий origin, поэтому защиту обеспечивает отдельный ключ и проверки обращений к Storage, а не папка URL. Формулы и JSON версии 1 остаются прежними.

Если не загружается страница, проверьте успешность Actions и настройки именно тестового репозитория; если виден старый экран — обновите страницу. Не очищайте всё хранилище браузера: рядом на том же origin могут находиться рабочие данные.
