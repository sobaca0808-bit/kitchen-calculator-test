# Выполненные проверки

Проверки выполнены в Chromium (Linux, Playwright) и Node.js. Тестовые цены существуют только внутри изолированных тестов, начальные данные приложения остались без цен.

## Расчёты — 15 тестов, пройдены

```sh
node tests/calculations.test.js
```

- 160 г и потери 37,5% → 100 г; обратный ввод выхода → процент потерь.
- 1 кг за 500 ₽, выход 600 г → 83,33 ₽ за 100 г готового; повторной ужарки нет.
- Фактический выход партии определяет цену готового грамма.
- Отсутствующие цены/количества/выход, пустые рецепты, частичная сумма.
- Пересчёт вложенных рецептов при изменении цены, циклы, безопасная обработка чрезмерной глубины.
- Масса и объём с явным коэффициентом и без него, масса штуки, нулевая цена, защита от нулевого знаменателя и переполнения.
- Вложенные черновики с повторяющимися ссылками не раздувают список ошибок экспоненциально.

## Данные — 11 тестов, пройдены

```sh
node tests/storage.test.js
```

Проверены точные начальные данные, JSON round-trip и восстановление, ошибки доступа/квоты localStorage, сохранность повреждённой исходной записи, невалидные схемы/числа/ссылки/единицы, циклы, согласованность потерь, безопасные идентификаторы и текст с HTML. Вложенность 100 уровней разрешена, 101 отклонена. Отдельно проверено 250 строк без ограничения количества ингредиентов.

## Браузер — 12 сценариев, пройдены

Само приложение ничего не требует устанавливать. Для повторения автоматических UI-проверок нужны Node.js, Python, Playwright и Chromium. Playwright можно установить отдельно от проекта:

```sh
npm install --prefix /tmp/kitchen-browser playwright
# В первом терминале, из папки проекта:
python3 -m http.server 8765 --bind 127.0.0.1
# Во втором терминале, из папки проекта:
NODE_PATH=/tmp/kitchen-browser/node_modules node tests/browser.test.js
```

По умолчанию используется `/usr/bin/chromium`. Для другого расположения задайте `CHROMIUM_PATH`; для другого локального адреса — `KITCHEN_TEST_URL`. В этой среде Playwright и Chromium уже были установлены.

Реально пройдены:

1. Начальный редактируемый гиро, девять строк, пустые цены, честный неполный итог.
2. Поиск с первой буквы по синониму, верхний регистр, выбор клавиатурой и мышью.
3. Согласование потерь и выхода, десятичная запятая/точка, отклонение отрицательных чисел и потерь 101%.
4. Сохранение ошибочного ввода при добавлении строки и его последующее исправление.
5. Редактирование продукта, перезагрузка и защита используемого продукта от удаления.
6. Добавление 30 строк, удаление строк, сохранение и перезагрузка.
7. Скачивание JSON, импорт с подтверждением, отмена замены и отказ при повреждённом JSON.
8. Исключение циклических ссылок из поиска и отклонение циклов при импорте.
9. Компоновки шириной 360, 390 и 430 px с эмуляцией касаний: отсутствие горизонтальной прокрутки, закреплённые итог и кнопки, доступность последнего поля при фокусе.
10. Отказ localStorage: предупреждение и возможность экспорта данных из памяти.
11. Создание через интерфейс продукта → полуфабриката → блюда: 83,33 ₽ за 100 г, отсутствие повторных потерь, изменение цены до 600 ₽/кг → порция 100 ₽; результат сохраняется после перезагрузки.

12. Отказ квоты при самом первом сохранении: заголовок честно сообщает, что данные только в памяти, а экспорт остаётся доступен.

Также визуально проверена настольная компоновка 1366 × 900 и мобильная 430 × 844. Во время сценариев исключений JavaScript не обнаружено.

## Что не проверено

- Открытие `index.html` через `file://` в управляемом браузере запрещено политикой среды (`ERR_BLOCKED_BY_ADMINISTRATOR`). Браузерные проверки выполнены через локальный HTTP. Для файлового запуска используются обычные скрипты и локальные стили, без ES-модулей, fetch и внешних ресурсов; подтверждения запуска через file:// на реальном ПК пока нет.
- Физическая мобильная клавиатура и реальные устройства, Safari и Firefox не проверялись. На мобильных ширинах нижняя панель уходит в обычный поток при фокусе поля редактора; её поведение с настоящей экранной клавиатурой требует проверки на устройстве.
- Публикация сайта и внешние сервисы не используются.

## Доработка технологических карт

Дополнительно выполнены проверки текущей версии:

```sh
node --test tests/calculations.test.js tests/storage.test.js tests/recipe-view.test.js
NODE_PATH=/tmp/kitchen-browser/node_modules node tests/browser.test.js
```

Результат: **31 тест логики и хранения, 16 браузерных сценариев — пройдены** (Chromium, Linux). Исходные формулы `js/calculations.js` не изменены.

Новые проверки охватывают временный пересчёт 1 → 10 и 2 → 10 порций, выход и потери, вложенный полуфабрикат без повторных потерь, массу штуки и коэффициент объёма, неизвестную массу, дробные значения и переполнение. Проверена неизменность исходных данных при пересчёте, импорт старого JSON и round-trip новых необязательных полей.

В браузере проверены отдельный просмотр и редактор, поиск и возврат, сохранение технологии как обычного текста, повторное сохранение без дубликатов, отмена ухода с несохранёнными изменениями, переключатель цен и блокировка печати при неверном количестве порций. Проверена дополнительная защита: повреждённая исходная запись не заменяется ни начальными данными, ни нажатием «Сохранить».

Проверены карточки на ширинах 360, 390 и 430 px без горизонтальной прокрутки. Созданы A4 PDF с ценами и без цен для карты из 90 строк и длинной технологии. Через извлечение текста подтверждены последняя строка 89 и технология; финансовые колонки и кнопки отсутствуют в PDF без цен. Проверки используют изолированные браузерные контексты и не обращаются к реальным данным кухни.

Физический принтер, реальные мобильные устройства, Safari и Firefox в этой среде не проверялись. Вызов печати использует стандартный `window.print()` и CSS `@media print`.
