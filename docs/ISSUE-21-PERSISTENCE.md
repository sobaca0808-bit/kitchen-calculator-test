# Issue №21 — сохранение именно эталонного /preview/

Работа ведётся только в `sobaca0808-bit/kitchen-calculator-test`, в отдельной ветке
`fix/issue-21-preview-persistence`. Основа — **`04c98fb20444859454fc18fd6f3d6e0429818f8b`**,
источник опубликованного PR №20 с тремя утверждёнными темами. Код PR №5/№6
рабочего репозитория не используется. Main, PR №20 и живая публикация не меняются.

## Что проверено на опубликованном адресе

Эталон: https://sobaca0808-bit.github.io/kitchen-calculator-test/preview/

Прямой доступ к github.io из рабочего окружения ограничен прокси. Поэтому
непосредственную проверку выполнил обычный Chrome на GitHub Actions, в новых
одноразовых профилях, без пользовательских данных и без публикации.
Проверены SHA-256 **56 файлов приложения**: 31 файл `/preview/` совпал с manifest
и исходником `04c98fb`, 25 файлов корня — с `63443c5`. Сам manifest также получен
по HTTPS и проверен по source commit, PR, namespace и контрольным суммам файлов.

Подтверждено, что корень репозитория и `/preview/` — разные версии и базы:

| Хранилище | Привычный `/preview/` | Корень тестового сайта |
| --- | --- | --- |
| База localStorage | `kitchen-calculator-preview-v1` | `kitchen-calculator-pr2-browser-test-v1` |
| Черновики | `kitchen-calculator-preview-drafts-v1` | `kitchen-calculator-pr2-browser-drafts-v1` |
| Фото IndexedDB | `kitchen-calculator-preview-photos-v1` | `kitchen-calculator-test-photos-v1` |
| Копии перед импортом | `kitchen-calculator-preview-import-backups-v1` | `kitchen-calculator-test-import-backups-v1` |
| Оформление | `kitchen-calculator-appearance-preview-v1` | `kitchen-calculator-appearance-test-v1` |

Пять активных namespace **не меняются**. В исходнике ветки остаются исходные
тестовые константы; существующий упаковщик `/preview/` заменяет ровно пять
строковых констант. Локальные проверки собирают тот же вариант и проверяют
точные пути `/kitchen-calculator-test/` и `/kitchen-calculator-test/preview/`.

## Подтверждённые причины видимого сброса

1. **Старая вкладка перезаписывает новую базу.** На опубликованном калькуляторе
   воспроизведено на 1366 и 390 px: одна вкладка сохраняет новый продукт,
   вторая, открытая раньше, меняет цену и сохраняет свою старую копию всей базы.
   Новый продукт исчезает; кнопка всё равно сообщает «Сохранено ✓».
2. **При отсутствии записи автоматически создаётся демо-база.** В чистом профиле
   опубликованный код записал 12 продуктов и 3 рецепта. При открытии другого
   namespace это может выглядеть как замена настоящей базы старыми примерами.
3. **Разные адреса читают разные namespace.** Открытие корня вместо `/preview/`
   показывает другой набор, хотя origin github.io общий.

При обычном полном закрытии/открытии Chrome без конкурирующей перезаписи
публикация сохранила созданные записи в трёх последовательных циклах на ПК и
мобильной ширине. Само по себе закрытие не воспроизвело удаление. Нельзя утверждать,
что все случаи на устройстве владельца имеют одну причину: другой профиль,
инкогнито и очистка данных браузером также могут сделать базу недоступной.

[Успешный аудит настоящей публикации](https://github.com/sobaca0808-bit/kitchen-calculator-test/actions/runs/43776804548/job/133004809997).
Его файлы и отчёты сохранены отдельно от исправленной копии в `issue-21/published`.

## Исправление

- Открытие читает сохранённую базу из того же активного ключа. При отсутствии
  показывает пустую библиотеку и предложение выбрать свой JSON; `Seed.create()`
  при запуске больше не вызывается, демонстрационные блюда не записываются.
- Обычное сохранение, папки и финальная запись импорта сравнивают исходную строку.
  Старая вкладка не перезаписывает обнаруженные новые данные. Её ввод остаётся на
  экране и доступен в отдельном JSON для последующего явного объединения.
- После записи проверяется чтение того же значения. Ошибка/тихий отказ не показывают
  «Сохранено ✓». Черновики также подтверждают свою запись отдельно от карточек.
- Изменённые скрипты получают общий параметр версии загрузки, чтобы при обновлении
  по прежнему адресу не смешивались старая копия из HTTP-кэша и новые API хранения.
  Параметр относится только к файлам JS и не меняет адрес/ключ пользовательской базы.
- Если запись могла состояться, но результат прочитать нельзя, сообщение честно
  говорит о неопределённом результате. Подготовленные фото не удаляются, поскольку
  уже записанная карточка может ссылаться на них. Копия до импорта сохраняется.
- Аварийный экспорт при неудачном сохранении включает валидные изменения открытого
  продукта или рецепта и новые фото, без повторной записи в основную базу.
- Папку можно явно сохранить и в пустой базе; предварительный импорт своего JSON
  в пустую базу также работает. Нет автоматического применения файла.

## Диагностика и ручное восстановление

Обычные здоровые экраны остаются прежними. Дополнительная помощь появляется
только при отсутствии/ошибке базы либо по явному адресу с `#storage-diagnostics`.
Это экран из существующих компонентов и цветов, без новых таблиц стилей.

Диагностика читает текущий и другие известные локальные источники только после
запроса пользователя. Показывает ключ, числа записей, папки, примеры названий/цен
и количество черновиков. Каждый исходный JSON можно скачать буквально, включая
повреждённую запись; черновики скачиваются отдельно. JSON с фото использует только
соответствующий источнику IndexedDB в режиме чтения. Отсутствующий чужой DB не создаётся.

**«Открыть проверку объединения»** использует уже существующий интерфейс импорта:
просмотр изменений, выбор конфликтов, отдельное применение, обязательная копия
текущей базы до записи. Изменившийся источник блокирует применение устаревшего
просмотра. Ничто не объединяется автоматически. Не выбирайте неизвестные старые
демонстрационные наборы вместо своей базы. Чужие ключи/фото/черновики не меняются.

Повреждённая активная база остаётся заблокированной от перезаписи, как в эталоне.
Сначала скачайте исходник; не очищайте хранилище ради обхода ошибки.

Обычный JSON содержит **сохранённые** продукты, цены, полуфабрикаты, блюда, папки,
упаковку, цену продажи и обе фотографии. Незавершённые черновики хранятся отдельно
и в такой экспорт не входят; их можно скачать отдельно в диагностике. Аварийный
экспорт после ошибки основной записи включает валидный открытый рецепт с фото.
Существующий формат version 1, расширенные поля и прежние JSON сохраняются.

## Проверка без публикации

Исправленный пакет проверяется на loopback-стенде с точными путями корня и `/preview/`
и прежними namespace. Создание производится через интерфейс: продукт с ценой
137,50 ₽, упаковка, полуфабрикат, блюдо, папка, две фото, цена продажи и черновик.
Три цикла полностью завершают Chrome и его драйвер. Новые процессы читают только
свою фактическую локальную базу; эталонные снимки из файлов теста обратно в браузер
не записываются. Дополнительно проверяется блокировка старой вкладки.

На GitHub Actions исправленная копия проверяется в обычном Chrome с HTTPS-адресом
эталона, **но ответы для этого временного браузера подменяются файлами кандидата**.
Это не публикация и не утверждение, что живой сайт исправлен. Владелец и другие
посетители продолжают получать прежний `04c98fb`. Проверки публикации без подмены
вынесены в другой job и другой артефакт.

Локальный Chromium 154 отменяет повторное скачивание после перезапуска даже на
минимальной странице без калькулятора. Поэтому локальный полный прогон задаёт
`KITCHEN_PERSISTENCE_DOWNLOAD_POLICY=first-process`: первая загрузка JSON проверяется
настоящим скачиванием, после рестартов — публичным API экспорта и байтами фото.
Chrome на GitHub Actions дополнительно проверяет **настоящий UI-экспорт во всех
трёх циклах**, без такого ограничения. Результаты различаются в JSON-отчётах.

Тексты/цвета/иллюстрации/геометрия обычных карточек, формулы, шаблоны A4 и просмотрщик
фото сохранены. Полный прежний набор проверяется в каждой из трёх тем. Подробности
и контрольные суммы — в [TESTING.md](../TESTING.md).

## Простые шаги владельцу после отдельного разрешения на выпуск

**Пока PR не проверен и публикация отдельно не разрешена, по привычной ссылке
остаётся прежний код. В этой задаче публикация не выполняется.**

1. Сохраните имеющийся резервный JSON отдельным файлом. Не очищайте данные Chrome,
   не переключайте профиль и не используйте инкогнито.
2. После разрешённого обновления откройте именно прежний `/preview/` в том же Chrome.
   Проверьте несколько знакомых названий, цену, папку, обе фото и черновик.
3. Закройте остальные старые вкладки калькулятора, полностью закройте Chrome,
   откройте его и ту же ссылку снова. Повторите три раза: записи должны появляться
   сами, без импорта. Ничего удалять из настоящей базы для такой проверки не нужно.
4. Если база отсутствует, откройте диагностику, сравните источники и скачайте их.
   Восстанавливайте только знакомые данные через просмотр объединения. Можно
   отменить просмотр — база не изменится. Сначала убедитесь, что резервный файл
   появился в «Загрузках».

Физический Android и настоящий принтер в среде не проверялись. Хранилище остаётся
локальным: пользовательская очистка, инкогнито и браузерные политики могут удалить
его независимо от приложения. Проверки исходных строк не являются общей атомарной
транзакцией между старыми/новыми вкладками, localStorage и IndexedDB; после обновления
важно закрыть старые вкладки. Неподтверждённая запись может оставить неиспользуемые
временные фото, которые намеренно не удаляются с риском повредить карточку.
