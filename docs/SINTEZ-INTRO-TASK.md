# Codex: интеграция приветственной презентации «СИНТЕЗ МЕРЫ» с главным экраном

## Контекст
Репозиторий: `sobaca0808-bit/kitchen-calculator-test`.
Существующий графитовый главный экран: PR #30, ветка `feature/sintez-home`, тест `https://sobaca0808-bit.github.io/kitchen-calculator-test/sintez/`.
Утверждённый локальный прототип презентации: `approved_presentation.html` в этом архиве. Кадры отдельно: `01_intro.jpg`, `02_home.jpg`, `03_chef.jpg`, `04_business.jpg`.
На main уже существует ДРУГАЯ старая страница `/welcome.html` — не заменять её неосмотрительно. Общий бэклог проекта: issue #29.

## Задача
Сделать безопасный интеграционный **тестовый стенд**: при первом осмысленном входе нового пользователя показать четыре утверждённых слайда, по кнопке «Начать работу» или «Пропустить» перейти на **существующий** графитовый главный экран из PR #30 с шестью действующими плитками. Никаких отдельных баз и дублирования расчётной логики.

## Утверждённые четыре слайда — порядок менять нельзя
1. Знакомство с «СИНТЕЗ МЕРЫ».
2. Для дома.
3. Для повара.
4. Для бизнеса — последний.

Использовать предоставленные изображения без новой генерации, искажения дизайна и обрезки важных элементов. Оригиналы в архиве — 1672×941 (практически 16:9). Тексты короткие, грамотные, соответствуют реально работающим возможностям. Иллюстративные экранные цифры и планшеты не представлять за реальные скриншоты действующего ПО.

## Навигация
- Визуальный набор и плавность утверждённой презентации сохранить, но создать настоящие рабочие переходы: «Назад», «Далее», индикаторы, свайп, клавиши стрелок, «Пропустить» и на последнем кадре «Начать работу».
- На первом входе нового пользователя показывать презентацию; после успешного «Пропустить» / «Начать работу» запоминать просмотр отдельным, именованным и версионированным ключом только тестового приложения. На повторных посещениях открывать сразу главный экран.
- Пользователям с существующими данными не навязывать презентацию и не создавать новую/пустую базу при просмотре. При ошибках чтения хранилища ничего не стирать и не объявлять «первый запуск».
- Из раздела «Настройки» дать кнопку «Посмотреть презентацию снова»; её просмотр не затрагивает рабочий контекст.
- Прямые ссылки `?section=...`, `#storage-diagnostics` и импорт/восстановление должны работать и не перехватываться приветствием. Корректно отрабатывать историю браузера, кнопку «Назад» и перезагрузку вкладки.
- Не делать кнопку «Установить приложение», если отсутствует реальный сценарий установки/подсказка по платформе. Слайды не должны ломать текущую PWA.

## Изоляция
- Не изменять `main`, продакшен-калькулятор, текущую `/pwa/`, старые `/welcome.html` и другие стенды. Не переписывать PR #30 и не объединять его без согласования владельца.
- Использовать отдельную ветку от `feature/sintez-home` (дочерний/stacked PR с явно указанной базой) и отдельный тестовый маршрут публикации, например `/sintez-intro/`; не перезаписывать существующую `/sintez/` до одобрения.
- Сохранить текущие продукты, рецепты, полуфабрикаты, расходы, фотографии, черновики, цены, формулы, импорт/экспорт JSON, печать. Не менять их схемы, ключи хранения, поведение редактора. Не создавать второй расчётчик или вторую базу.
- Не добавлять внешние runtime-зависимости. Картинки локальные, не скачиваются с посторонних CDN.

## Проверки и приёмка
1. Чистый тестовый пользователь: видит 4 слайда; можно листать мышью, клавишами, точками и пальцем; последний «Для бизнеса»; обе кнопки входа приводят к графитовому экрану.
2. Повторный вход: сразу шесть рабочих плиток. «Настройки → Посмотреть презентацию снова» открывает те же 4 кадра и без потери состояния возвращает в приложение.
3. Открытие прямых ссылок на разделы и диагностику не перехватывается презентацией.
4. Открытый несохранённый рецепт/черновик и фото не исчезают при возврате, переключении, обновлении; данные не переписываются.
5. Проверить 320/390/768/1024/1366+ px, портрет и альбомную ориентации, мышь/сенсорный ввод, клавиатуру, офлайн (если применимо), уменьшенную анимацию (`prefers-reduced-motion`), кликабельные кнопки и читаемый текст. Минимальные сенсорные цели ~44 px.
6. Прогнать существующие тесты PR #30, включая сохранение, JSON и печать; добавить тесты первого/повторного запуска и переходов.
7. Опубликовать отдельно изолированный тестовый URL, дать отчёт о тестах, скриншоты ПК и телефона, ссылку на PR. Указать, что на реальном Android всё равно нужна ручная проверка владельца.

## Порядок действий Codex
Сначала проверить структуру ветки PR #30 и текущую публикацию, затем реализовать интеграцию в отдельной ветке; протестировать; вернуть ссылку на новый изолированный стенд. **Ничего не объединять в main** и не менять существующие ссылки без отдельного подтверждения пользователя.
