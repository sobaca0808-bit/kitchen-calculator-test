# Расходы внутри калькуляционной карточки

Основа — PR №23, коммит `1c1fcc0`. Используется его существующий расчёт расходов;
формулы продуктов, упаковки, полуфабрикатов, продуктовой маржи и распределения
месячного плана не переписываются.

## Как пользоваться

1. Откройте сохранённое блюдо в форме **«Калькуляционная карта»**.
2. Под ингредиентами и **«Упаковкой и фасовкой»**, перед итогами, находится блок
   **«Учитывать расходы заведения»**. Для старых и новых блюд без выбора он выключен.
3. При включении выбор сразу сохраняется именно для этого блюда. Видны расходы
   на порцию; список **«Расходы по статьям»** можно раскрыть. Главный итог включает
   продукты, упаковку и расходы. Исходный итог без расходов и продуктовая маржа
   остаются отдельно. Повторного сохранения рецепта не требуется.
4. Выключение возвращает обычную калькуляцию продуктов и упаковки. Месячные статьи,
   план продаж и выбор других блюд остаются прежними.

Если план не настроен, показывается объяснение и переход во вкладку расходов.
Неизвестные суммы не заменяются нулём: полный итог пока не рассчитан, а известная
база продуктов и упаковки остаётся видимой. После сохранения плана включённые
карточки получают новые суммы автоматически, без ручного переноса.

## Контрольный пример

Для автоматической проверки создана учебная карточка «Гиро в булке куриное большое»
с суммами из задания. Реальная рецептура и база владельца не читались и не копировались.

- Продукты: **188,44 ₽**.
- Упаковка: **3,90 ₽**.
- Обычный итог: **192,34 ₽**.
- Месячные расходы 222 000 ₽ / план 3 000 порций дают **74 ₽** на порцию.
- Итог при включении: **266,34 ₽**.

В приложении нет фиксированной надбавки 74 ₽. Изменение аренды или зарплат меняет
сумму из общего плана, а порции просмотра масштабируют её без изменения рецепта.
Упаковка учитывается прежним механизмом один раз. Накладные расходы добавляются
только на готовое блюдо, без начисления на вложенные заготовки.

## Сохранение и JSON

В объект блюда добавлено одно необязательное поле:

```json
"includeEstablishmentExpenses": true
```

Это булево значение, только для блюда. Отсутствие означает выключенный режим;
загрузка старой базы не вставляет false автоматически. Формат остаётся version 1.
Флаг переносится вместе с рецептом, фотографиями и прочими полями. При конфликте
объединение использует прежний явный выбор версии; повторный импорт не плодит копии.

Нажатие меняет только флаг выбранного блюда: количества, ингредиенты, выход,
закупочные цены, фото и метаданные упаковки сохраняются. Запись проверяется
чтением и исходной строкой базы. При квоте или старой вкладке переключатель
возвращается к сохранённому состоянию с понятным сообщением; чужие данные не затираются.

При восстановлении старого черновика его незавершённые поля сохраняются, а выбор
расходов берётся из актуальной сохранённой карточки. Старый черновик не отменяет
более позднее переключение; сам черновик при переключении не переписывается.

## Печать

При включённых расходах в управлении печатью доступен выбор **«Статьи расходов
при печати»**: **«Только итоги»** или **«С детализацией»**. Раскрытие экранного списка
не влияет на этот выбор. В первом варианте остаются финансовые итоги, во втором
печатаются также статьи. Все кнопки и сам переключатель скрыты.

Для печати без всех цен и финансовых сумм выберите существующую **«Карту повара»**.
Сохранённый выбор расходов блюда от смены формы не меняется. Прежние четыре
варианта фотографий продолжают работать. Формат детализации — временная настройка
просмотра/печати, как выбор фото; в JSON сохраняется сам выбор учёта расходов блюда.

## Проверка

Новые сценарии проверяют обе суммы из примера на 1366/390 px, расположение блока,
раскрытие списка, независимость двух блюд, перезагрузку и настоящий JSON-экспорт/
импорт, аренду/зарплаты, пустой план, квоту и старую вкладку, черновик и A4.
Прежние проверки трёх тем, фотографий, упаковки и расчётов сохраняются.

Отдельный адрес нового стенда — `/expense-toggle/`, с пятью собственными именами
хранилищ. Прежние `/preview/`, `/pr-22/`, `/expenses/`, main и рабочий репозиторий
не обновляются. Новая база пустая, автоматического переноса данных нет. Можно
явно импортировать свой JSON через просмотр объединения. Фактическая публикация,
снимки и отчёт фиксируются в
[отчёте стенда](https://github.com/sobaca0808-bit/kitchen-calculator-test/blob/preview/browser/preview-hosting/expense-toggle/PUBLICATION.md).

Мобильные проверки выполняются эмуляцией Chrome, физический Android и настоящий
принтер требуют ручной проверки. Слияние с main и обновление прежних стендов
возможно только после отдельного согласования.
