# Выпуск согласованной версии PR 25

Рабочий адрес сохраняется: https://sobaca0808-bit.github.io/kitchen-calculator-test/.
Рабочий репозиторий `kitchen-calculator` не изменяется; выпуск относится к main
репозитория `kitchen-calculator-test` после разрешения владельца.

Код приложения совпадает с утверждённым `662a12a`. PR 20 → 22 → 23 → 24 включены
одной последовательной историей. Новые функции и формулы не добавляются.

## Что делает публикация

1. Проверяет предков коммита, отсутствие изменений в коде приложения относительно
   утверждённой версии и полное совпадение имён хранилищ.
2. Собирает root из выпускаемого коммита main. Сохраняет пять прежних стендов
   `/preview/`, `/pr-22/`, `/expenses/`, `/expense-toggle/`, `/final/` побайтно из
   проверенной публикации `f9e1df3`: 180 файлов, 175 HTTPS-ответов.
3. Меняет только заголовок/отметку теста в публикуемом HTML на рабочую версию и
   даёт всем JS/CSS единый параметр версии. Исходные JS/CSS и формулы не меняются;
   старый кеш браузера не смешивает модули разных выпусков.
4. Перед публикацией сверяет прежние 200 HTTPS-ответов и проверяет обновление
   старой базы в одноразовых профилях. После публикации проверяет 212 ответов,
   реальные сценарии расходов, JSON, фото, A4 и закрытие/повторный запуск Chrome.

## Данные

Сохраняются прежние имена основной базы, черновиков, фотографий, резервных копий
и оформления. Имя основной базы остаётся `kitchen-calculator-pr2-browser-test-v1`:
переименование при выпуске потеряло бы доступ к существующим данным.

Сборка не имеет доступа к данным браузера пользователя, не очищает их и не
записывает туда демо. При открытии имеющаяся база читается с прежними ключами.
JSON version 1, неизвестные дополнительные поля, ссылки и оба фото совместимы.

Базы разных URL-версий ранее были специально изолированы. Они остаются на своих
местах. Записи из `/final/` или другого тестового адреса не заменяют базу корня
автоматически. При необходимости владелец явно экспортирует JSON с нужного
адреса и импортирует его в рабочую версию через просмотр объединения с копией.

- Добавлены 2 сценария перехода старый main → новый выпуск → полный перезапуск

  черновик, настоящая резервная копия и оформление. Проверяется отсутствие

- Старый main в проверке перехода моделируется ответами fixture только на первом
  запуске. Новый опубликованный выпуск загружается непосредственно по HTTPS,
  без подмены его ответов. Все записи и изображения проверки искусственные.

`release-version.json` содержит фактический коммит main, исходные/опубликованные
хеши и имена хранилищ; он не содержит данных пользователя. Журналы, снимки и PDF
сохраняются в артефакте GitHub Actions `kitchen-release-proof`.

Физический телефон уже проверен владельцем на утверждённой финальной версии.
Автоматические проверки выпуска используют Chrome, включая мобильный экран и
касания; физический принтер не используется.

## Согласование со старым автоматическим издателем Pages

В настройках репозитория Pages использует режим `legacy`: при изменении main
GitHub отдельно запускает `pages build and deployment`. Он публикует сырой корень
репозитория без тестовых каталогов. У токена Actions нет административных прав
отключить этот режим (API вернул 403); адрес сайта и настройки остаются прежними.

Поэтому явный выпуск дожидается завершения автоматического издателя именно того
коммита main, который выпускается, и затем публикует полный подготовленный пакет.
Проверка до выпуска принимает только известные состояния: прежний main, тот же
готовый выпуск при повторном запуске или побайтно совпадающий с утверждённым
кодом сырой main. Только в последнем состоянии допускаются отсутствующие (404)
тестовые файлы для восстановления. Изменённые существующие тестовые файлы или
неизвестное приложение блокируют публикацию. После выпуска все 212 ответов
обязаны существовать и совпадать с хешами; исключений для 404 больше нет.

Изменение файлов сервера не удаляет localStorage или IndexedDB пользователя.
Восстановление возвращает прежние URL и прежний код с прежними именами хранилищ.
