# Issue №32: единая основа «СИНТЕЗ МЕРЫ» и безопасный путь выпуска

## Уточнение владельца: публичный вход и установленный ярлык

Публичная презентационная ссылка —
`https://sobaca0808-bit.github.io/kitchen-calculator-test/sintez-release/presentation.html`.
Она всегда начинает с первого слайда, независимо от рецептов, оформления,
черновиков и признака прошлого просмотра. Повторный переход и перезагрузка
снова показывают первый слайд; «Пропустить» остаётся доступной. Параметр
`?presentation=1` также поддержан новым runtime, но для публичной ссылки выбран
новый HTML-путь: прежний Service Worker мог вернуть по прежнему пути старый
закешированный index.html. Только изменённые JS/CSS презентации получили новые
имена файлов; старые рабочие окна продолжают использовать свой полный кеш.

Последний слайд содержит «Открыть программу» и «Установить приложение».
Кнопка установки синхронно обращается к кнопке существующего PWA-клиента,
только если тот получил настоящий beforeinstallprompt. Иначе показываются
инструкции Android Chrome, Windows Chrome/Edge и iOS Safari. Отмена не
называется успешной установкой; подтверждение берётся из appinstalled.
Сам PWA-клиент и Service Worker не изменены.

Существующий start_url `./?source=pwa` и настоящее standalone-окно открывают
рабочее меню даже без признака просмотра и без сохранённой базы. Явный публичный
параметр действует отдельно. Прямые ссылки на рабочие разделы, импорт и
диагностику имеют приоритет и обходят презентацию. Повторный просмотр из
настроек сохраняет текущую работу и возвращает в настройки.

Пять имён хранения, id/scope/start_url всех существующих PWA и утверждённые
изображения остаются прежними. Замороженная новая основа будет закреплена
отдельным тегом `release/sintez-unified-candidate-v2` после успешного CI;
тег v1 не переносится. Обновляется только прежний отдельный `/sintez-release/`,
без публикации main или рабочей `/pwa/`. Дополнительный браузерный набор
проверяет публичный вход с данными/без них, повторные входы, отмену/отсутствие
установки, Back/Forward, диагностику и установленный старт. Отдельный native-тест
проверяет запуск настоящего свежего ярлыка без признака просмотра.

Основа — объединённый PR №31 в PR №30, коммит
`59fce080ea4e8dd90dc8cd86e2361323bc81cd3a`. Владелец подтвердил работу этой
презентации и главного экрана на реальном Android и компьютере.
Работа выполняется в `release/sintez-safe-release`, отдельным дочерним PR
в `feature/sintez-home`. Main и рабочие публикации до согласования не меняются.

## Обнаруженные ограничения прежнего выпуска

Старый `scripts/release-pages.py` допускает только runtime `662a12a`: обычное
слияние PR №30 вызовет отказ сборки. Набор сохраняемых путей содержит пять
старых стендов и PWA, но не `/sintez/`, `/sintez-intro/` и новый единый стенд.
Поэтому одного GitHub merge недостаточно: нужен проверенный новый сборщик.

PWA фактически опубликована в `/kitchen-calculator-test/pwa/`, а не в корне.
Её id — `/kitchen-calculator-test/pwa/`, start_url — `./?source=pwa`,
scope — `./`, display — `standalone`. Пять имён начинаются с
`kitchen-calculator-pwa-` и отличаются от корня и SINTEZ-стендов.
Нельзя заменить их тестовыми данными или переименовать ради нового бренда.

В старой истории есть стандартный Pages branch publisher и собственный
workflow. Новый основной выпуск требует **Source: GitHub Actions**: иначе
push в main может отдельно опубликовать сырое дерево и убрать старые маршруты.
CI читает `build_type` через Pages API без изменения настроек и сохраняет
результат в `pages-config.json`. Если чтение недоступно, владелец должен проверить
Settings → Pages → Build and deployment → Source до любого слияния main.
Никаких настроек этот PR автоматически не меняет.

## Что подготовлено

- Один runtime: те же четыре кадра, бизнес последний, шесть реальных плиток,
  прежние рабочие формы, фото, упаковка, расходы, печать, черновики и JSON.
- `scripts/sintez-package.py` связывает этот runtime с явным существующим
  пространством хранения. Web сохраняет ключи нынешнего корня, PWA — свои пять
  старых ключей. Новый `/sintez-release/` использует общую прежнюю тестовую базу
  `/sintez/` и `/sintez-intro/`, а не базу рабочей PWA.
- Только признак презентации новый для web/PWA: прежней презентации в этих
  приложениях не было. Флаг отделён от рецептов, JSON и данных тестовых стендов.
  Существующая база или черновик исключает навязанное приветствие.
- Новый сборщик `scripts/release-sintez.py` восстанавливает прежнюю публикацию
  из закреплённого `08f80c5`, сохраняет все старые пути, затем готовит отдельные
  предлагаемые web/PWA-пакеты. Ничего не публикует и не открывает профиль браузера.
  Замороженный единый стенд сохраняется из тега
  `release/sintez-unified-candidate-v1`, который создаётся после успешного CI.
- Основной workflow на push main только проверяет и сохраняет артефакт.
  Выпуск доступен отдельным ручным `workflow_dispatch` с `publish_release=true`,
  после проверки неизменного main, единственного Actions publisher и всех старых
  HTTPS-файлов. Неизвестный/неполный сайт никогда не считается безопасной базой.
- Алгоритмы Service Worker и PWA-клиента скопированы побайтно из проверенной
  версии `11784f1`. Нет skipWaiting, clients.claim или принудительной перезагрузки.
  Новая статическая копия проверяет SHA-256 каждого файла, ждёт закрытия старых
  окон, хранит одну полную предыдущую копию. localStorage/IndexedDB не очищаются.
- Существующие PWA-кнопки размещаются в видимом старом заголовке приложения,
  сохраняя DOM и обработчики. Новых функций калькулятора и улучшений Issue №29 нет.

## Фирменная иконка

Все файлы из `sintez_mery_brand_icons.zip` сохранены в `icons/sintez/` без
генерации, ретуши, изменения цвета, композиции или масштаба. Исходный PNG
1254×1254 сохранён для проверки; в runtime используются готовые небольшие файлы.
Фавиконки ICO/16/32, Apple 180 и manifest 192/512 с отдельными maskable 192/512
сверяются по контрольным суммам архива. Название — «СИНТЕЗ МЕРЫ», short_name —
«Синтез меры». id/start_url/scope рабочей PWA остаются точными прежними.

CI проверяет реальную установку через Chrome Web App backend и отдельное
standalone-окно, обновление старой установки без удаления и новый тестовый ярлык.
Скриншоты native Chrome/Windows и Linux относятся только к одноразовым профилям.
ОС может некоторое время показывать прежнюю иконку/название установленного ярлыка:
новый manifest и файлы доступны сразу, системное обновление зависит от Chrome/ОС.
Нельзя обещать мгновенную замену, требовать удаления PWA или очистки данных.
Реальный Android после изменения иконок и обновления PWA проверяет владелец.

## Проверки

Полный CI запускается после объединения #31: 253 теста логики, 715 прежних
браузерных сценариев во всех темах, 29 презентации и 12 главной на окончательной
PWA-сборке. Дополнительные проверки: оригинальные иконки, полнота кеша,
воспроизводимость, точные ключи/identity, строгий release verifier и путь main.

PWA-сценарии обслуживают старую и новую версии на одном origin/path с одной
установкой и настоящими SW. Проверяют ожидание закрытия нескольких окон,
незавершённую форму, черновик, цены, две фото по SHA-256, расходы, папки,
упаковку, офлайн-перезапуск, A4/JSON, защиту чужих хранилищ и кешей, отказ
повреждённого обновления. Отдельно проверяется настоящий desktop install.
Данные синтетические; реальные профили и резервные копии владельца не используются.

## Следующий шаг владельца

1. Проверить отдельный единый стенд, ярлык, офлайн, JSON, фото и печать.
   Если сразу видна главная, открыть «Настройки → Посмотреть презентацию снова».
   Тестовый устанавливаемый ярлык имеет собственный preview-id: старая рабочая
   PWA остаётся установленной, её не удалять.
2. После отчёта явно подтвердить основной выпуск. Проверить/при необходимости
   согласовать Source: GitHub Actions **до** слияния main. Сначала объединить
   этот дочерний PR в `feature/sintez-home`, затем PR №30 в main.
3. Дождаться проверок main, запустить основной workflow вручную с
   `publish_release=true`. Установленный адрес `/pwa/` останется прежним;
   сохранятся его id, стартовый URL, scope и все пять имён данных.
4. Сохранить открытые формы, закрыть все окна старой PWA и запустить её снова.
   При переходе между разными браузерами/профилями или пространствами хранения
   перенос возможен только явным JSON-экспортом/импортом с просмотром изменений.

Никакого автоматического переноса SINTEZ-тестов в рабочую PWA и автоматического
слияния main в рамках этой задачи не выполняется. Опубликованный отчёт должен
отдельно указать фактический статус CI, Windows/Android и основной публикации.
