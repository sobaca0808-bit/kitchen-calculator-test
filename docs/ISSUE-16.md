# Issue №16: безопасный ручной перенос и объединение JSON

Ветка `feature/safe-json-merge` подготовлена владельцем от проверенного `768335afd74dde6f254b727c449e5c4aadbdcb2a`. Этот же коммит является контрольной точкой main, release/v1.0-candidate-2026-11-12 и backup/verified-pr14-2026-11-14. Разработка не изменяет эти ветки, Pages или рабочий kitchen-calculator. PR предназначен для ручной приёмки, без автоматического слияния и публикации.

## Аудит до применения изменений

Текущая база JSON версии 1 содержит products и recipes; опционально packaging и folders. ID уникальны во всей базе, включая строки ингредиентов и упаковки. Ингредиент ссылается через refId на продукт или готовый полуфабрикат; ingredientRefId в упаковке защищает от двойного учёта. У блюда может быть folderId. Ссылки, единицы, циклы и глубина рецептов проверяются KitchenStorage.

Основная база хранится в изолированном localStorage `kitchen-calculator-pr2-browser-test-v1`. Черновики — отдельно в `kitchen-calculator-pr2-browser-drafts-v1`; фото — в IndexedDB `kitchen-calculator-test-photos-v1`. Локальная база содержит photoId/photoIds; обычный JSON-экспорт включает photo/photos с самими снимками. Версия 1, старые записи без папок/цены/фото поддерживаются. Файлы до 50 МБ, до двух снимков по 500 КиБ на рецепт; версия выше 1 отклоняется.

Риски прежнего импорта: нет просмотра изменений, только полная замена; общий persist оставляет результат в памяти при неудачной записи; разрешённые будущие JSON-поля отбрасывались allowlist-проверкой. Безопасный импорт должен обходить этот путь записи и сохранять исходную базу при любой ошибке.

## Алгоритм и конфликтная политика

1. Прочитать и проверить файл; получить переносимую копию текущей базы со снимками. До применения основная база и фотографии не меняются. Незавершённая рецептура остаётся отдельным черновиком.
2. Показать два режима: **«Объединить»** по умолчанию и **«Заменить базу»** с явным предупреждением. Предварительный просмотр показывает добавления, обновления, пропуски, конфликты и удаления при замене.
3. Сопоставлять сущности по ID и полному содержимому, а не только по имени. Равные записи пропускаются. Разные записи с одним ID или именем требуют решения. Для сущностей доступны **«Оставить текущую»** и **«Сохранить обе версии»**. Незаметное обновление общего продукта могло бы изменить калькуляции других блюд, поэтому точечная автоматическая перезапись не используется. Полная замена — отдельное осознанное действие.
4. Сохраняя обе версии, выделить устойчивые новые ID и различимые названия, переназначить известные ссылки по всей импортируемой цепочке и проверить результат целиком. Повторное применение того же файла не должно создавать очередные копии. Удаления в режиме объединения отсутствуют.
5. Безопасные дополнительные JSON-поля сохраняются. Конфликты корневых дополнительных полей разрешаются отдельно выбором текущего или импортированного значения. Неизвестные смысловые ссылки нельзя угадывать: сохранённые поля с переназначенными ID должны сопровождаться предупреждением. Неподдерживаемые поля метаданных фото явно отклоняются, поскольку существующее хранилище снимков не может надёжно вернуть их в экспорт; молчаливой потери нет.
6. Перед применением записать полную резервную копию текущей базы со снимками в отдельную IndexedDB `kitchen-calculator-test-import-backups-v1` и дать возможность скачать её. Ошибка создания копии блокирует применение. Черновики не заменяются, старые снимки не удаляются.
7. Подготовить новые снимки, повторно проверить исходную JSON-строку, затем одной атомарной записью сохранить проверенную базу. При ошибке убрать только новые временные снимки. Изменённая другой вкладкой база отменяет применение и требует нового просмотра.

Это ручной перенос файлов между устройствами, а не синхронизация в реальном времени. Ни облачного хранилища, ни фонового обмена нет.

## Хранение и границы защиты

Полная копия до применения записывается в отдельную IndexedDB, проверяется повторным чтением и доступна в блоке **«Копии перед импортом»**, в том числе после перезапуска браузера. Хранятся до трёх последних копий; нужную копию следует скачать на устройство. Прежние копии удаляются только после успешной записи и проверки новой. Неизменившийся повторный импорт не записывает базу и не расходует место на новую копию.

Основная база сохраняется одним атомарным localStorage.setItem. LocalStorage и IndexedDB не образуют общую транзакцию: сначала надёжная копия, затем подготовка фото и последняя проверка исходника, затем запись. При обычной ошибке убираются только новые временные фото. При аварийном закрытии между этапами могут остаться неиспользуемые временные фото, но исходная база и предыдущие фото не удаляются. Неизменившиеся снимки повторно не записываются.

Web Locks, если доступны, последовательно выполняют импорты в разных вкладках. Проверка точной исходной JSON-строки отменяет применение при замеченных внешних изменениях. Это не полноценная транзакционная синхронизация между всеми вкладками и устройствами: во время применения не редактируйте базу в другой вкладке.

Если текущая база повреждена или не сохранена в браузере, автоматическое применение блокируется. Для повреждённой записи есть отдельная кнопка скачивания исходника без изменений; фото и черновики не очищаются. Такой случай требует отдельного восстановления, поскольку полную достоверную резервную копию нельзя получить из нечитаемой базы.

После полной замены ID старого черновика может быть занят записью другого типа. Восстановление такого черновика блокируется с пояснением, сам черновик сохраняется; для его восстановления можно вернуться к копии до импорта. Если черновик создавался новым, а ID уже принадлежит рецепту того же типа, требуется подтверждение перед восстановлением. Ошибка отображения после успешной записи сообщает, что данные уже сохранены, и предлагает обновить страницу; она не выдаётся за откат.

Безопасные расширения JSON сохраняются с ограничениями: до 100 уровней JSON, до 500000 значений, общий бюджет 50 МиБ. Прототипные ключи, вычисляемые свойства, циклы, функции и прочие значения вне JSON отклоняются явно. Неизвестные поля метаданных фотографии тоже отклоняются явно. Локальные photoId без самих снимков работают только на устройстве, где сохранились эти фото; для переноса нужен обычный экспорт со снимками.

## Проверка на телефоне и компьютере

Проверять нужно **предпросмотр ветки feature/safe-json-merge этого PR**. Существующий сайт Pages не обновляется этим PR и пока не показывает новые функции. Все действия ниже одинаковы в Chrome на компьютере и телефоне. Для надёжного сравнения используется Web Crypto: на телефоне нужен HTTPS-предпросмотр, на компьютере подходит также localhost. Для применения нужны доступные localStorage и IndexedDB; при их запрете исходная база не заменяется. Физический Android и принтер требуют ручной приёмки; автоматические мобильные проверки используют размеры и сенсорный режим Chromium.

1. Нажмите **«Экспорт JSON»** и сохраните текущую тестовую базу на устройство. Это отдельная копия, которая не зависит от хранения трёх последних автоматических копий в браузере.
2. Скачайте [учебную базу устройства A](fixtures/issue-16/device-a.json) и [базу B с другой ценой](fixtures/issue-16/device-b-price-change.json). В GitHub кнопка скачивания исходного файла находится справа вверху. Цены и рецепты вымышленные; не использовать их как производственную рецептуру.
3. Нажмите **«Импорт JSON»**, выберите файл A. Убедитесь, что по умолчанию выбрано **«Объединить»**, видны счётчики и список изменений. Нажмите **«Отмена»**: основная база должна остаться прежней. Снова выберите A и примените. Добавится учебная папка с блюдом и двумя связанными полуфабрикатами.
4. Откройте **«Учебное блюдо — JSON16»**. Продуктовая себестоимость одной порции — **25 ₽**, с упаковкой — **30 ₽**, цена продажи — **300 ₽**. Для продукта сохранено дополнительное учебное поле, оно должно вернуться в JSON при экспорте.
5. Импортируйте файл B. Цена риса в нём 160 ₽ вместо 100 ₽; должны появиться **четыре конфликта** по продукту и цепочке рецептов. Откройте **«Сравнить содержимое»**. Пока решения не выбраны, кнопка применения недоступна. Выберите **«Оставить текущую»**: исходное блюдо не должно подорожать.
6. Ещё раз выберите B и **«Сохранить обе версии»** для всех конфликтов. Импортированная цепочка получит различимые имена с пометкой **«(импорт …)»**. У исходного блюда по-прежнему 25/30 ₽, у импортированного — **40/45 ₽**; оба относятся к учебной папке. Общий продукт исходных рецептов не перезаписывается.
7. Повторно выберите B. Новых копий появиться не должно; просмотр сообщает, что изменений нет. Отмените просмотр. Проверьте поиск и обе карты, варианты фото и печать A4.
8. В блоке **«Копии перед импортом»** скачайте нужную копию. В отдельной чистой тестовой среде выберите её, включите **«Заменить базу целиком»**, проверьте предупреждение и число удалений, подтвердите применение. Копия с фотографиями должна восстановиться; сама замена также требует успешной копии предыдущей базы.
9. Для проверки фото прикрепите к учебному блюду два тестовых снимка, сохраните, экспортируйте и повторите перенос в чистую среду. Проверьте оба снимка, папки, упаковку, цену продажи и расчёты. Закройте и снова откройте браузер: результат и автоматическая копия должны остаться.
10. Оставьте несохранённую правку рецепта и дождитесь **«Черновик сохранён»**. Выполните перенос другой базы, затем восстановите черновик: его данные не должны исчезнуть. Изменения черновика попадают в карточку только после обычного сохранения.

## Автоматические проверки

Финальный полный `scripts/check-preview.mjs` завершился с кодом **0**: **198 Node-проверок и 194 браузерных сценария Chromium**, без ошибок. Прежние 133/161 сохранены; добавлены 11 проверок расширений JSON, 27 модели объединения, 27 транзакции, 25 сценариев нового интерфейса и 8 сценариев настоящей IndexedDB.

- Модель проверена на 1000 блюд: старые/пустые JSON, полные дубли, одинаковые имена с разным составом, совпадения ID разных типов и строк, вложенные цепочки, цена, папки, упаковка, дополнительные поля, неправильные сочетания решений. Повторный импорт не размножает копии, в том числе после удаления исходных записей или более ранней импортированной копии.
- Прежняя `KitchenPackaging.resolveLinks` применяется к проверенным представлениям до сопоставления и перед записью. Это сохраняет служебный ingredientRefId, защищающий от двойного учёта после переименований. Проверены повтор старого файла без этого поля и перенаправление связи на скопированный продукт. Формулы упаковки не менялись, резервная копия остаётся буквальным прежним снимком.
- В браузере проверены просмотр/отмена, оба режима, каждый вариант конфликта, повторное применение, импорт без фотографий и с двумя фото, неизменность исходных ID/байтов снимков и черновиков, старый однофотографический формат, настоящий экспорт/импорт, повреждённый файл, неподдерживаемая версия и файл больше 50 МиБ.
- Реальная IndexedDB подтверждает запись/повторное чтение копии, совместный откат backup/metadata, ошибки квоты копии и основной базы, ошибку второй фотографии, изменение исходника во время подготовки фото, хранение трёх копий и сохранение после настоящего перезапуска Chromium.
- При запрете localStorage запуск и экспорт не ломаются. Запрещённый getter IndexedDB не ломает создание сервиса; безопасное применение отклоняется. Отдельные проверки подтверждают защиту коллизий черновика и правдивое сообщение при ошибке экрана после успешной записи.
- Новый просмотр проверен с 200 связанными импортируемыми блюдами на фактических 320/390/1366 px, без горизонтальной прокрутки; конфликт цены — также на телефоне. Скриншоты просмотрены визуально. Прежние наборы дополнительно проверяют библиотеки из 500 записей, финансы, фото, черновики, поиск, папки, обе формы карты и печать A4, включая длинные таблицы и компактное гиро.

Прежние импортирующие тесты теперь явно выбирают режим замены и применяют просмотр, сохраняя защитные утверждения. Фото-фикстуры отката используют действительно новые снимки, чтобы корректная дедупликация не превращала тест ошибки в no-op. Прежняя проверка удаления неизвестных полей заменена проверкой их сохранения согласно Issue №16.

Все проверки используют только loopback, вымышленные данные и временные контексты/профили; настоящая кухонная база не используется. Учебные файлы отдельно проверены планировщиком: четыре конфликта, продуктовая себестоимость 25/40 ₽, полная 30/45 ₽, повторный файл не добавляет записей. Физический Android и принтер не проверялись. Состояние release, main, резервной ветки и настройки публикации этой работой не изменяются.
