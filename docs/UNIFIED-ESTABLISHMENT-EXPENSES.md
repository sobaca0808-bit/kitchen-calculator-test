# ТЗ42: единый раздел «Расходы заведения»

Основа: PR41, `4cc596363f37b99b8341a822e959fe9a4b28e950`. Отдельная ветка `feature/unified-establishment-expenses`, PR направлен в `feature/financial-journal`, чтобы не дублировать родительские изменения. Main, PR38/40/41 не изменяются.

## Один ввод и одна история

Семь компактных раскрываемых блоков: выручка, итоги, постоянные расходы, налоги, материалы, пользовательские папки, распределение. Журнал и календарь — представление тех же сохранённых операций; кнопка в журнале открывает исходную карточку, второй формы ввода нет. Месячный итог выручки показан последним днём месяца, а не вымышленной дневной операцией.

Папки используют прежние категории PR41 и те же ID. Переименование сохраняет связи; удаление после подтверждения переносит все расходы и исторические месячные изменения в «Прочие расходы». Рецепты не затрагиваются. Архивные категории и записи доступны. Папки без вложенности.

Карточка содержит название, сумму, дату, категорию, периодичность (разово / ежемесячно / ежегодно), включение, метод учёта, признак накладного расхода и примечание. Изменение регулярного платежа действует в выбранном месяце, удаление — только на это вхождение; завершение серии останавливает будущие автоматические повторения. Уже явно сохранённые изменения будущих месяцев не удаляются. Для смены даты начала или частоты — завершить старую серию и создать новую.

## Учёт и формулы

Деньги журнала хранятся целыми копейками. В месяце активен ровно один метод выручки: сумма дневных записей; месячный итог; средняя дневная × рабочие дни. Неактивные значения сохраняются, но не прибавляются. Средняя выручка помечена оценкой.

Расходы разделены на оплаченные, начисленные обязательства, оценки и старые записи PR41 без указанного метода. Старые записи не выдаются за подтверждённую оплату. Будущие автоматические регулярные платежи — оценки до явного подтверждения за месяц.

Методы отчёта: денежный (оплаченные), начисление (оплаченные + начисленные), плановый (все включённые, включая оценки и неопределённые старые записи). Отдельные суммы остаются видны при любом методе. При оплате обязательства меняется метод той же записи, не создаётся второй расход.

- Расходы метода = сумма включённых в метод записей.
- Доля расходов = расходы / активная выручка × 100 (при нулевой/неизвестной выручке — не рассчитано).
- Финансовый остаток = выручка − расходы выбранного метода. Это не чистая прибыль; продуктовые затраты и обязательства могут быть внесены не полностью.
- Предыдущий месяц сравнивается тем же методом.
- Налоги вводятся вручную с названием, датой и отчётным периодом; налоговых автоматических формул нет.

## Распределение на блюда

Источник выбирается явно кнопкой «Сохранить и применить [месяц] к блюдам». Просмотр другого месяца не меняет активный расчёт. Используется один источник: старый сохранённый план ИЛИ активный месяц журнала, никогда их сумма.

В распределение входят включённые записи с признаком «Накладной расход», соответствующие выбранному методу учёта. Аренда, коммунальные, зарплата, канцелярия, уборка, ремонт по умолчанию накладные. Налоги, оборудование, пользовательские и прочие расходы требуют осознанного выбора. Упаковка никогда не распределяется повторно. На полуфабрикаты надбавка не начисляется. Неопределённые старые накладные требуют уточнения метода либо явного планового режима.

- По порциям: накладные / плановое число продаваемых порций.
- По выручке: накладные / выручка месяца × цена продажи порции.
- Себестоимость с расходами = продуктовая себестоимость + существующая упаковка + одна надбавка.
- Расчёт на несколько порций масштабируется существующим механизмом.

Цена продажи должна быть задана для режима по выручке; ноль допустим и даёт нулевую надбавку. Пустая цена/выручка, нулевой знаменатель, переполнение не подменяются вымышленными суммами. Продуктовая маржа остаётся отдельно. Прежний флажок рецепта управляет отображением расходов и финансовой печатью; карта повара без цен сохранена.

Прежний план сохранён для совместимости и виден только для чтения. Безопасный перенос показывает предварительный список: статьи с уже существующими записями категории за месяц пропускаются, отсутствующие копируются как оценки с детерминированными ID. Повторный перенос не создаёт дублей. Исходный план не удаляется. Дробные копейки требуют ручной проверки, исходное значение не округляется автоматически.

## Совместимость и хранение

Опционально расширен `financialJournal`: метод учёта, заметка, накладной флаг, удалённая папка; в месяце — настройки отчёта/распределения, в корне — активный месяц. Старые JSON без этих полей принимаются. Экспорт включает все новые поля; при объединении старый JSON не стирает новые настройки. Реальные конфликты требуют существующего предварительного просмотра и выбора. Движок хранения/CAS, фото IndexedDB, черновики, резервные копии, формулы продуктов/полуфабрикатов, печать и Service Worker защищены побайтовой проверкой относительно PR41 (85 прежних файлов).

Тестовый стенд `/sintez-expenses/` использует собственные имена `kitchen-calculator-expenses-*`, отдельные черновики, фотографии, резервные копии и флаг презентации. Переноса данных между стендами автоматически нет. Начальная база пустая. Для переноса пользователь сам экспортирует JSON и импортирует его с просмотром изменений.

## Ручная проверка на Android и ПК

1. Открыть тестовую ссылку в Chrome → «Для бизнеса» → «Расходы заведения».
2. Выбрать месяц. В выручке выбрать месячный итог и сохранить 1 500 000 ₽.
3. Добавить оплаченные аренду 100 000, зарплаты 300 000, коммунальные 50 000, налог 50 000, канцелярию 1 300. Создать папку «Оборудование» и разовую плиту 80 000 без признака накладного.
4. Денежные итоги: 581 300 ₽ расходов, остаток 918 700 ₽, доля ≈38,753 %. В журнале — те же шесть расходов и один месячный итог.
5. Из журнала открыть запись, изменить дату/сумму/папку, сохранить. Проверить изменение без второй записи. Проверить отмену удаления, переименование и удаление папки с сохранением расходов.
6. Переключить месяц: разовая плита не повторяется, регулярные платежи будущего месяца — оценки. Переключить способ выручки: старые суммы сохраняются, не складываются.
7. Применить распределение по порциям с планом 1000: накладные 451 300 / 1000 = 451,30 ₽. По выручке при цене блюда 300: 451 300 / 1 500 000 × 300 = 90,26 ₽. Упаковка и плита повторно не начисляются.
8. Сохранить JSON, закрыть приложение/Chrome, открыть снова, проверить записи и фотографии. После первой полной загрузки повторить запуск и изменение офлайн. Импортировать JSON с предварительным просмотром; повторить импорт — дублей быть не должно.
9. Проверить карточку блюда, флажок расходов, печать с финансовой детализацией и карту повара без цен. Проверьте реальный Android: автоматические проверки используют Chrome с мобильным разрешением, физический телефон владельца не подключён.

## Ограничения

Локальное браузерное хранение не заменяет внешнюю резервную копию JSON. Финансовые формы сохраняются явно; несохранённые поля защищены предупреждением. Нет автоматического расчёта налогов/амортизации, распределения фактических продаж по блюдам, отрицательных возвратов, нескольких валют или вложенных папок. Никаких новых модулей вне ТЗ42 и редизайна.
