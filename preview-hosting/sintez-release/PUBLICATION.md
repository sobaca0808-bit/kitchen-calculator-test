## Базы и PWA

Новый стенд использует существующую общую **тестовую** базу `/sintez/` и
`/sintez-intro/`: `kitchen-calculator-sintez-preview-v1` и прежние SINTEZ-имена
черновиков, IndexedDB фото, копий и оформления. Тестовое редактирование будет
видно между этими тремя SINTEZ-адресами. Новая база и автоматический перенос
не создаются. Данные рабочей PWA и старых отдельных стендов не подставляются.

Устанавливаемый новый тестовый стенд имеет собственный manifest id
`/kitchen-calculator-test/sintez-release/` и не заменяет рабочую установку.
Рабочая `/pwa/` сейчас **не обновлена** и сохранена побайтно.

Для будущего основного выпуска подготовлена та же единая оболочка, связанная
с точными прежними ключами корня и отдельно с ключами фактической `/pwa/`:

Алгоритмы Service Worker и клиента взяты побайтно из проверенной `11784f1`.
Обновление не очищает базы, не вызывает skipWaiting/clients.claim и не

## Важный результат аудита: до main требуется решение владельца

Фактическая настройка Pages — **legacy, source main /**.
[Прямой ответ Pages API из CI](evidence/integration/pages-config.json).
Обычное слияние main может запустить независимый branch publisher, который
обойдёт безопасный сборщик и заменит старые пути сырым деревом репозитория.
Поэтому main в этой работе не объединён и настройки не изменены.

Для безопасного основного выпуска нужно отдельно согласовать и выполнить
переход **Settings → Pages → Build and deployment → Source: GitHub Actions
до любого слияния main**. Если такого разрешения нет, оставить main и рабочую
PWA как есть. Подготовленный новый workflow сам настройки не меняет: push main
только проверяет сборку, а публикация требует отдельного ручного запуска с
`publish_release=true`, точного актуального main, Source=workflow и успешной
проверки всех 400 ранее опубликованных ресурсов. Неизвестный сайт не принимается.

## Короткая ручная проверка и следующий шаг

1. Открыть ссылку в Chrome телефона и ПК. Если сразу показана главная,
   открыть **Настройки → Посмотреть презентацию снова**. Проверить четыре слайда
   и «Начать работу», затем все шесть плиток.
2. Проверить тестовый продукт/цену, блюдо с двумя фото, расходы, черновик,
   перезапуск, JSON и печать. Это общая SINTEZ-тестовая база: перед изменениями
   полезно экспортировать её JSON. Перенос между разными базами выполняется
   только явным импортом с предварительным просмотром, не автоматически.
3. Для нового тестового ярлыка: меню Chrome **Установить приложение** либо
   **Добавить на главный экран → Установить**. Дождаться в «Приложение» сообщения
   **Готово к запуску без интернета**, закрыть и открыть через ярлык без сети.
   Старую рабочую PWA не удалять. При установке в другом браузере/профиле не
   ожидать общей базы: безопасный перенос — экспорт/импорт JSON.
4. После проверки отдельно подтвердить основной выпуск **и переход Pages
   Source на GitHub Actions до main**. Затем можно объединить PR №33 в
   `feature/sintez-home`, PR №30 в main, дождаться полного CI и вручную выпустить
   основной workflow с `publish_release=true`. Адрес рабочей `/pwa/` сохраняется.

Ни основного выпуска, ни автоматического переноса баз, ни слияния PR №30/33
в рамках этого отчёта не выполнялось.
