## Публикация

Пошаговые настройки Pages для Issue №2 и проверка владельцем находятся в [PAGES.md](PAGES.md). Ничего в рабочем репозитории менять не нужно.

Владелец сообщил, что тестовый GitHub Pages уже включён по адресу `https://sobaca0808-bit.github.io/kitchen-calculator-test/`. Новый хостинг и новый репозиторий не нужны. Этот PR добавляет проверки и инструкции; пользовательские функции приложения остаются прежними.

Рабочий репозиторий `kitchen-calculator`, его `main`, рабочий GitHub Pages и PR №2 не изменяются. Настройки публикации нельзя переключать на другую ветку для проверки этого PR. Если нужно принять изменения, объединять можно только PR в **тестовом** репозитории после проверки владельцем. Если существующий Pages публикует `main` тестового репозитория из корня, он заберёт принятые изменения обычным способом.

Доступ к настройкам Pages из текущего подключения отсутствует. Поэтому ветка/папка публикации не считаются проверенными только по наличию файлов в репозитории. Из облачной среды запрос к публичному адресу был отклонён прокси (`CONNECT 403`, в Chromium — `ERR_TUNNEL_CONNECTION_FAILED`); это ограничение среды, а не доказательство неисправности сайта у владельца. Новая публикация в рамках этого PR не выполнялась.

## Изоляция данных

- Приложение использует только `kitchen-calculator-pr2-browser-test-v1`.
- Рабочий ключ `kitchen-calculator-v1` не читается и не записывается; миграции или автоматического импорта из него нет.
- Все образцы и цены в проверках вымышленные. Браузерные сценарии создают отдельные временные контексты, без профиля владельца.
- Экспорт имеет префикс `kitchen-calculator-PR2-TEST-`. Формат JSON версии 1 и действующие формулы не меняются.
- Разные проекты GitHub Pages одного владельца имеют общий origin `https://sobaca0808-bit.github.io`. Изоляцию текущего приложения обеспечивает отдельный ключ, а не имя папки сайта. Поэтому проверяются фактические обращения к хранилищу и сохранность вымышленной контрольной записи в рабочем ключе.

Тесты разрешены только на localhost и точном пути тестового сайта. Перед действиями проверяются тестовый ключ и отметка «ТЕСТ». Очистка всего localStorage не используется.

## Повторить автоматические проверки

Сам калькулятор не требует установки пакетов. Для проверки нужны Node.js, Chromium и Playwright. Если Playwright ещё нет:

```sh
npm install --prefix /tmp/kitchen-browser playwright
NODE_PATH=/tmp/kitchen-browser/node_modules node scripts/check-preview.mjs
```

Скрипт сначала проверяет расчёты и JSON, затем сам поднимает временный сервер на `127.0.0.1`, запускает браузерные сценарии и закрывает сервер. Внешний опубликованный сайт не посещается. Для браузера вне `/usr/bin/chromium` задайте `CHROMIUM_PATH`.

## Проверка владельцем на телефоне

1. Откройте существующий адрес тестового сайта в Chrome. На странице должна быть отметка «ТЕСТ PR №2».
2. Создайте вымышленный продукт и рецепт. Сохраните, откройте карточку, измените число порций и перезагрузите страницу: исходный рецепт должен сохраниться.
3. Выберите показ цен «ДА», затем «НЕТ» и проверьте оба варианта через «Печать» → «Сохранить как PDF».
4. Экспортируйте тестовый JSON и импортируйте его обратно. Отмена импорта должна оставить тестовые записи без изменений.

Для этой проверки не нужно загружать рабочие резервные копии. Фото блюд, новые режимы пересчёта и следующие обновления исключены условиями Issue №3.
